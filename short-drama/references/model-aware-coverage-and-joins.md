# 按模型排生成段，按观众体验接镜

本页是段长、分组与接镜策略的唯一权威，项目已接受选择记录于 short-drama.json；分镜时就读本页；视频提示词、生产与剪辑复用同一安排。目标是让观众跟住动作与情绪，生成调用的边界尽量不被察觉。

## 镜头与生成段是两回事

SHOT 是观众看到的一次镜头表达；clip 是一次模型调用产生的素材。一次调用可含多个镜头，一个长镜头也可能跨调用。先定镜头的注意与情绪职责，再结合项目所选模型、实际应用的时长/参考/多镜能力、重试成本，决定调用数量和边界。

### 三层约束：能力、入口建议、项目选择

1. **[官方接口契约]**：H3 整数时长4–15秒；Seedance 2.5 显式整数时长4–30秒。具体任务的自动时长、编辑/延长语义读目标方言。实际入口可能更窄，项目规格不能突破接口能力。
2. **[入口实测建议 / 待项目校准]**：高风险交互、密集信息或精密端点变化可先比较5–10秒短段；稳态连贯对白可评估H3 10–15秒、2.5 12–20秒，后者在入口样片稳定且节拍有需要时再评估25–30秒。这些是试拍起点，不保证短段更便宜或成片率最高；没有对应回片记录时只称制作建议，不称已验证甜点。
3. **[项目已接受规格]**：读取 short-drama.json 的 production_profile 与已接受 rhythm_profile；在实际接口可行域内安排生成预算和成片目标，不改写用户已定节奏，不用容量上限填满空等。

### 模式边界也是分组边界

路线选择由[分镜](../../short-drama-storyboard/SKILL.md#生成路线分流)负责，接口细节由目标方言负责。已核对的H3与BytePlus 2.5标准接口中，首尾帧条件与全能参考输入互斥；需要不同控制路线的镜头分开调用，或明确选择同一条可行路线，不暗中牺牲端点条件。端点约束不保证中间表演或像素级渐变，仍须回片验证。其他供应商入口另核，不泛化。

先按故事内容尝试较长分组，再把调用边界放到自然段落、时空变化或适合接镜的位置。短尾段、独立插入镜、复杂动作或定向补拍按实际需要取短；通过完整动作、反应和可剪余量利用时长，不靠拉慢表演或静止等待凑上限。

在《分镜.md》的场景站位附近，用一行 `- 生成安排：` 写模型/实际模式、预计调用次数、各段 SHOT 范围与生成时长、成片目标窗口、关键跨段依赖。简单的一镜一次直接简写。跨段处在对应 SHOT 下写 `- 接镜：`，说明相邻 SHOT、接法、动作阶段/视线/运动方向、声音与可剪余量。沿用原 SHOT/MOTION ID，调用序号只在这场里标识分组。

现有 SHOT/MOTION「时长」字段继续遵守当前投产契约；更短的成片目标写在生成安排里，实际裁切留给后期。生成时长是素材预算，成片窗口是剪辑意图；回片后由真实动作和发声决定采用源窗。多镜打包沿当前执行器已接通的入口；只支持单条 source_entry 的路线按可提交镜头排调用，先补覆盖而非纸面宣称少调用。

## 多段生成先找整组可行段界

必须拆成多个生成段时，段界是整组约束求解，不是每段独立寻找“离平均长度最近”的切点：

1. 保留已接受镜长与表演，先列出真正适合断开的剧情/镜界；可剪余量、锚点和实际生成时长逐段计入容量。
2. 用 `ceil(总生成占用/单段上限)` 得到段数下界，再检查是否存在一整组不超过上限的合法边界；下界不是可行证明。
3. **整组可行先于均衡。** 每个候选边界都同时检查前段、后段及剩余内容能否成立；局部最近导致剩余超限时回溯，
   不直接多加一段，也不压快说、删反应或拉伸镜头。
4. 可行组合中再优先完整交流、动作链、反应落定与时空变化，随后比较均衡和短尾段；创作断点比平均秒数重要。
5. 当前段数无解才增加段数或回分镜调整镜界/分组。成片窗口、实际素材长度和重叠采用区间继续分别记账，
   顺接相加，重叠按实际保留并集，不靠分组消灭真实占用。

算术例：镜长 `3、9、2、7`，单段上限 10，各镜界均合法且无余量。理论下界是 3 段；逐个接近平均位置可能得到
`3/11/7`，其中第二段超限。整组回溯后可用 `3/9/9`，无需加成四段。此例只演示容量组合，实际最短生成时长与
入口能力仍须另核，段界最终仍要满足观看与接续。

## 四种接法，主动选择

| 接法 | 导演与生成安排 | 回片后看什么 |
|---|---|---|
| 自然切镜 | 注意交给听者、道具或新的空间信息；让构图/景别/机位变化足以被读作新镜头 | 视线、轴线、方向、光态与信息顺序 |
| 动作匹配切 | 同一动作在不同角度继续；两边拍够接触前后和运动过程，成片选择相容的动作阶段 | 手、道具、重心、方向和速度；匹配是感知连续，不机械要求像素或时间完全相同 |
| 连续长镜头 | 尽量在一次可承载的调用内完成；跨调用时从上段实际采用出口承接姿态、运动与声音 | 运镜是否重启、动作是否停一下、背景/光色是否跳变 |
| 有意转场 | 时空、情绪或段落变化可用遮挡、甩镜、声音桥、叠化或黑场 | 转场是否表达变化，关键动作是否仍看得懂 |

同一主体、相近构图与相近机位容易造成无意跳切：可拉开景别或机位差，约 30°是常用参照，也可切反应/物件。相邻景别和小角度切换在动作、情绪或有意跳切中仍有用途，选择以正常速度观看为准。保持空间轴线与视线关系，比凑一个角度数字更重要。

过渡镜头有自己的职责：看见被注视的物件、听者迟疑、动作后果或空间变化。气口留给呼吸、尾字、反应与观众理解；动作切可以在运动中发生，连续镜头的段尾继续运动，不因需要剪辑余量就统一站住等切。

## 从计划传到真实素材

1. **分镜**写生成安排与接镜；声音、剪辑意图、关键帧围绕它们选覆盖。H3 必须拆段时，优先找反应、动作交接或视点变化，减少近似构图的独立片段硬接。
2. **提示词**读取这些行，把本次调用实际承担的动作、镜头内切点、进入/退出状态及可剪余量写进目标模型正文。后续段从“正在进行”接写，只展开这段的新增过程；角色和场景锚点继续保持。分组与调用备注留在正文外。
3. **生产**对需依赖前段的任务先看已生成结果。在现有制作记录登记采用文件/版本、出口源时间与对应帧、动作阶段和后续依赖。取帧位置与实际出口对应，计划关键帧和文件最后一帧不自动等于采用出口。改换前段或出口后重看依赖它的后段，能靠剪点修的先修。
4. **剪辑**将采用源窗写进 `film.html`，用 `data-shot-id` / `data-motion-id` 关联来源，必要时在 `data-sd-intent` 简记接法。依据实际重叠内容修剪重复动作；共同上下文才适合去重，任意两段叠化不等于运动连续。
5. **回看**先正常速度看接点前后，再逐帧定位姿态、机位、光色、重复/冻帧与音轨突变。调整源窗、换覆盖、匹配光色、连续底声和 J/L cut；素材缺了动作或身份漂移时定向补段。结论留在既有制作记录，接点页是可重建预览，不是另一份时间线或新审批。

## 当前路线与真正运动续接

单张出口帧主要约束姿态和构图；速度、节奏和运镜靠本地观察后写入正文，效果仍需回片比较。当前 creator-first 选择器解析图与角色音频；本机 RunningHub 视频参考停用时继续沿用该策略。普通独立生成采用明确的自然切镜/动作切，而非默认承诺同镜无缝。

若已选服务提供视频上下文或 latent 续接，沿其真实接口承接已采用尾窗，并按返回的上下文区间对齐/去重。latent 固定、普通视频参考、单帧条件是三种不同能力。原片风格参考与本项目已生成尾窗分开评估；本次指南不会自动打开视频槽或替换 RunningHub 工作流。

## 简例：约26–28秒的同场戏

高密动作可以比较8+10+8秒的独立段，稳态交流可以比较两个13–14秒连贯段。两者只是候选，先检查每段声音、动作、控制模式与余量是否装得下；出现单独FL2V需求时在该处重新排段。选择依据是实际样片、接镜与重试成本，不预判哪种成片率最高。成片目标与生成预算分别记账。

依据：[Seedance 2.5 官方能力](https://docs.byteplus.com/ko/docs/modelark/seedance-2-5)、[Adobe 跳切与 30°参照](https://www.adobe.com/creativecloud/video/discover/jump-cut.html)、[H3 Motion Context](https://github.com/NikoDemon80/ComfyUI-H3-Motion-Context)、[RunningHub 2026-11-02 工作流](https://www.runninghub.ai/post/2102239919971270657)。社区工作流的采样/重叠参数只适用于对应实现，不作为本套件统一门槛。

接口核对（2026-11-25）：[BytePlus API](https://docs.byteplus.com/en/docs/modelark/create-video-generation-task-api)、[MiniMax官方CLI校验](https://github.com/MiniMax-AI/cli/blob/main/src/video/v2.ts)。创作建议不等于接口保证。
