# 视觉依据与输入参考图规范

本页只在填写或修订「视觉依据」「图片提示词项」「输入参考图」时读取。三条依据都描述同一格关键帧，
但身份不同：`IMG-...` 是提示词条目，`REF-...` 是项目内真实图片，`PLAN-...` 是创作者生成时自行挂载的计划。

## 视觉依据

冻结关键帧成稿后，按实际画面反查需要保持身份、造型或地理的可见人物、地点和道具，逐项写：

```text
《视觉设定.md》·<人物|造型|地点|道具>「<名称>」（控制：<范围>）
```

`《视觉设定.md》·` 只写一次，多项用 `；` 连接，名称必须能在《视觉设定.md》里找到同名标题。
小比例或背景人物只要需要认出身份仍在范围内；画外人声和不可识别局部不算。确实没有这类条目时写
「视觉依据：无」，但正文点名的条目仍须核对。

正文提到的条目实际不在画面里时，在末尾追加 `；画外：<类别>「<名称>」`。条目名称容易误匹配时，
由 `$short-drama-assets` 在该条目写 `画面代称：无`；是否实际入画仍由视觉依据如实回答。

「控制」只写这一格承担得起的范围：手背特写不写「本集造型」，屏幕和一根手指不写「体态」。
上一镜的绑定不因人物仍在这场戏里自动顺延。检查器只抓被条目名或画面代称点到的内容；
正文用匿名描述时，仍须人工把实际可见对象读出来。

需要保持一致、但《视觉设定.md》还没有条目的可见物件，逐镜使用相同描述，并在末端报告中请
`$short-drama-assets` 补条目。分镜不自行新增资产，也不把不存在的条目写进视觉依据。

## 图片提示词项

已有合适条目时写 `IMG-...`、中文名称和本镜控制范围，ID 必须匹配《图片提示词.md》的可见二级标题。
ID 只用于查找，不代表图片已生成、已提供或可用，也不靠英文 slug 承担含义。

没有文档或没有合适条目时写「图片提示词项：无」，直接引用《视觉设定.md》的文字事实。
这是正常入口，不为分镜编造 ID 或补造阶段。图片提示词条目与真实参考图可以独立存在。

## REF：项目内真实图片

只有创作者已提供，或经确认生产且当前可读的图片才能写成 `REF-...`。每个槽位逐字使用：

```text
REF-<slot>（顺序：<n>）· <项目相对路径>《<中文名称>》（用途：<用途>；控制：<范围>；不得控制：<范围>）
```

路径只用 `/` 分隔。多图只用中文分号 `；` 连接，顺序从 1 连续编号。`用途` 只能取
`身份`、`造型状态`、`地理`、`构图`、`尺度`、`效果`、`起始帧`、`结束帧`、`风格` 之一；
逐条含义见 `$short-drama` 的《参考角色》。一张图承担两件事就拆成两个槽位。
一镜最多一张 `起始帧` 和一张 `结束帧`，写 `结束帧` 时必须同时有 `起始帧`。

本镜起始画面图写 `起始帧`，人物图写 `身份` 或 `造型状态`，场景图写 `地理`，道具状态图按它决定的
那一件写。自动绑定只选本镜可见且确实需要稳定的图，逐张写清能控制与不得控制什么，不按资产数量凑槽位。

一张都没有时写「无（待补参考图：<本镜缺失的起始帧、人物、地点、道具>）」；只缺一部分时保留已有
`REF-...` 或 `PLAN-...`，末尾追加「；待补参考图：<缺口>」，缺口之间用 `、` 分隔。
只有创作者明确表示不用图时，才写「无（创作者已明确选择文生视频）」。

## PLAN：创作者在项目外备图

语法与 `REF-...` 相同，只把项目相对路径换成本项目已有的 `IMG-...` 或 `SHOT-...` 条目 ID：

```text
PLAN-<slot>（顺序：<n>）· <IMG-... 或 SHOT-...>《<中文名称>》（用途：<用途>；控制：<范围>；不得控制：<范围>）
```

`IMG-...` 的中文名称必须与《图片提示词.md》标题一致。`PLAN-...` 只声明生成时由创作者按此顺序挂载，
不声称项目里有文件，因此不是待补，也不能交给 `$short-drama-produce`。真实文件进项目后改写成 `REF-...`。
两种槽位可以混用，`顺序` 统一连续编号。

本镜起始帧可由 `$short-drama-produce` 按当前 `SHOT-...` 的冻结关键帧生成，或由创作者在外部工具生成。
套件内生产的 image job 以 `剧集/<EP>/分镜.md` 和当前 `SHOT-...` 为来源，真实文件进入
`剧集/<EP>/制作成果/images/` 后再绑成 `REF-...`。创作者自备且不进项目时，可写
`PLAN-SHOT-START` 指向本镜 `SHOT-...`。

## 完成检查

- 三条依据是否来自同一格画面，视觉依据是否覆盖实际可见对象？
- `IMG-...` 是否只当提示词 ID，`REF-...` 是否都是当前可读真实文件？
- 每个槽位的顺序、路径或条目 ID、中文名称、用途和控制边界是否完整？
- 待补、创作者自备、明确文生视频是否被区分，部分绑定是否保留？
- 是否只绑定本镜真正需要的图片，没有让上一镜或资产清单替本镜做决定？
